# VGA666 GPIO display output

Pi-DOS can drive a standard VGA666 resistor-ladder adapter on the GPIO header,
using Linux DRM/KMS. **System > Enable VGA666** in `PIDOSCFG` selects this output;
it is disabled by default. The Windows tool exposes the same saved setting.
This feature requires a rebuilt image containing the new kernel, supervisor
and BOOT assets; it is newer than the published 1.1 image.

## Enable or disable

1. Run `PIDOSCFG` and open System. Scroll to **Enable VGA666** and check it.
2. Choose CRT for native DOS timing changes, or LCD for a fixed output mode.
   The monitor and adapter must accept the selected modes.
3. Select USB audio or the board's analogue jack if needed. VGA666 carries no
   audio, and HDMI video is disabled while this output is selected.
4. Save with F2, then perform a clean `REBOOT` or `POWEROFF`. Apply does not
   activate GPIO output. The supervisor updates BOOT during clean shutdown.
5. With power off, connect the VGA666 board and monitor, then start the Pi.

To return to HDMI, uncheck the option, Save and cleanly reboot or power off.
System Restore defaults disables VGA666, pending Save and clean shutdown.
Windows settings remain save-only; exit Windows and reboot Pi-DOS afterward.
Removing power immediately after Save does not synchronize BOOT.

## Board families

The image retains the existing model-specific graphics overlays and adds the
shared upstream `vc4-kms-vga666` overlay after them:

| Board family | Base graphics overlay | DPI implementation |
| --- | --- | --- |
| Pi 2/3, Zero 2, CM0/CM3 families | `vc4-kms-v3d` | VC4 DPI |
| Pi 4/400, CM4/CM4S families | `vc4-kms-v3d-pi4` | VC4 DPI |
| Pi 5/500, CM5 families | `vc4-kms-v3d-pi5` | RP1 DPI |

Both overlays apply successfully to all 18 shipped board device trees in the
focused host check. This verifies device-tree integration, not physical output
on every board. GPIO signals must be accessible on the board/carrier; the
original Pi Zero and other non-ARM64 targets remain outside this image.
The upstream RP1 driver notes reduced colour precision with standard VGA666
GPIO wiring; a Pi 5 is not promised full 18-bit colour through this pinout.

## Hardware and modes

Standard VGA666 uses GPIO 2–21. Do not use other devices on those signals at the
same time. Pi-DOS disables the header UART while VGA666 is enabled to avoid
conflicting with GPIO 14/15, and restores the normal boot configuration when
disabled. The VGA666 overlay's optional DDC bus stays disabled. Wiring VGA DDC
directly to GPIO 0/1 is not supported; those pins are not 5 V tolerant.

Pi-DOS supplies an analog EDID in initramfs, retaining the HDMI profile's
standard and custom CRT video timings while removing HDMI/audio metadata.
The VGA connector is forced on because an ordinary resistor adapter has no
hotplug detection. The supervisor selects its DRM card, including the separate
RP1 DPI card on Pi 5. CRT/LCD rendering, screenshots and Turbo notices use the
existing presentation path. VGA666 adds no 15 kHz arcade/SCART timing profile.
Check individual modes with your display; 720x400 at 70 Hz is the startup mode.

## BOOT files, updates and recovery

`[pidos] vga666=true/false` in `C:\SYSTEM\PIDOS.CFG` is the saved preference.
Firmware cannot read that data file directly. At clean shutdown, PID 1 resolves
BOOT as partition 1 beside the actual data partition, verifies the Pi-DOS MBR
signature and BOOT label, and mounts it temporarily. It replaces only the
managed `pidos-video.txt` include using a synchronized temporary file and
rename; custom `config.txt` content and the original `cmdline.txt` are retained.

The enabled include disables the UART, loads `vc4-kms-vga666`, and selects
`pidos-vga666.txt` as the kernel command line. That alternative forces VGA-1,
disables HDMI, and loads `edid/vga666.bin`. The disabled include returns to the
normal HDMI boot path. Missing assets, an unmanaged include or a stale
`pidos-video.new` cause an update failure rather than an overwrite. Errors are
reported through supervisor diagnostics; the saved preference remains available
for another attempt.

An Image-only update cannot add this feature to an older card. Install matching
BOOT configuration, the managed include, alternative command line and overlay,
as well as the new Image. Back up BOOT customizations before updating.

If VGA output is unusable, shut down and open BOOT on another computer. Replace
`pidos-video.txt` with the project's disabled template (the managed header,
`[all]`, and a comment; no overlay or `cmdline=` assignment). Set
`vga666=false` in the data partition's `SYSTEM/PIDOS.CFG` too, so the next clean
shutdown does not enable it again. Preserve any interrupted temporary file for
inspection before removing it.

## Implementation and checks

`src/init/video_boot.c` handles BOOT synchronization and DRM discovery.
`tools/image/vga666.py` generates the analog EDID and alternative command line.
The simple-bridge kernel patch honors firmware EDIDs even without a DDC bus.
Image verification checks the assets, kernel drivers and every overlay chain.
Run `python3 tools/image/test-vga666.py` after building the pinned kernel trees.
Actual VGA666 picture, colour, mode switching and Pi 5 GBM/EGL operation still
need hardware acceptance.
